# DeepSeek Harness 接入准备度

版本：1.0 · 2026-10-26
状态：只读资料/代码评估，未批准实施；本轮不安装、不配置、不接入。

## 依据与判断边界

用户希望未来在青松的教学助手区域接入 DeepSeek Harness。本次核对的是官方 [`deepseek-ai/deepseek-harness`](https://github.com/deepseek-ai/deepseek-harness) 及其 [架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)，查阅日期2026-10-26。官方将其标为developer preview，存在不兼容变更；本评估没有固定发布版本或提交，实施前必须重新核对版本和SDK协议。

框架提供插件化的模型适配、工具注册、会话日志与Agent循环，并有SDK应用配置。它可以承担执行引擎；青松的业务接入层仍需明确设计。没有运行官方安装命令、下载依赖、配置密钥或调用模型，没有把教师数据发送给框架或模型。

## 青松已有基础

- `server/context/workspaceContext.ts`、`server/middleware/authenticated.ts`：教师身份、工作区与数据/上传路径隔离；HTTP鉴权与同源变更检查已存在。
- 班级、名册、课表/日程、课堂检查与表现、批改、材料池和资料检索已有业务服务/接口。`server/routes/resources.ts` 已有搜索、资料详情和检索入口，不能称作“没有知识检索”。
- 课堂任务已有预览凭证、版本校验、operationId幂等、追加事件、结果核对；这些是可复用基础，不代表所有业务写入都已有相同保护。
- `server/services/multimodal/OpenAICompatibleProvider.ts` 等已有针对具体任务的模型调用；没有因此形成教学助手的持续会话/工具执行循环。
- 当前教学助手仅为UI预留区；代码检索未发现对应聊天会话、Agent运行或流式会话路由。

## 主要缺口

| 能力 | 需要补齐的青松接入层 |
| --- | --- |
| 会话与运行连接 | 教师/工作区到Harness会话、运行、事件日志的映射；前端发送、流式显示、停止、继续和刷新恢复。优先评估官方SDK连接，具体事件协议/生命周期需按固定版本验证，不自行再造整个执行循环 |
| 业务工具 | 将现有服务封装为有输入/输出契约的工具或插件，如查课表、查课堂记录、搜资料、预览提醒；携带真实ID、结构化错误与来源。写入走已有业务服务，不让Agent直接改SQLite |
| 当前上下文 | 显式传教师、班级、学生、项目、课次、日期和时区；明确“正在查看”与“允许操作”范围。按需取资料/历史，不能假设模型能看到React页面状态，也不能默认塞入全部学生资料 |
| 人工确认与纠错 | 聊天内显示将改什么、影响谁、预览差异、确认/取消与提交回执；将审批绑定到具体动作/参数/版本，复用课堂幂等和结果核对模式。提醒等其他写入需补齐适合自身的保护，避免断线重试重复创建 |
| 证据与可观测性 | 对话结论绑定资料页、课堂事实或任务ID，可点击回原页面；工具执行、部分失败、重试和最终保存结果有明确记录，不能仅给一句“已完成” |
| 运行治理与验收 | 后台Agent在HTTP请求结束后仍须绑定正确身份/工作区；配置执行权限、凭据管理、配额/成本、超时/取消、重启恢复与版本隔离。Harness通用执行能力按教学工具范围配置；测试跨班同名、越工作区、写入待确认、响应丢失等真实场景 |

以上是当前代码与官方架构的差距判断，不是“框架不具备这些能力”。例如框架会话日志和工具管线应复用，青松负责业务身份绑定、工具适配和用户可见反馈。具体宿主部署、并发容量与SDK生命周期尚未验证。

## 建议的最小接入顺序（仅供后续讨论）

1. 先验证一个教师会话，以及“今天有什么课”“查本班最近课堂记录”“从我的资料找依据”三个只读工具闭环；能显示来源、停止生成、刷新续接。
2. 再接一个需确认的写入，如“明天下午三点提醒收作业”：预览实际日期/时区/班级，教师确认后保存，断线后核对同一操作。
3. 最后再扩展批改、画像解释、跨任务协作及其他自动化。教案目前仍是预览入口，应单列真实生成/保存契约，不能当作现成可调用工具。

不建议把官方Web界面直接当作青松现有会话区的替代，也不预先假定独立Web服务已经满足青松多教师鉴权；优先保留现有UI，通过服务端连接引擎和受控业务工具。正式选型时再确认SDK、运行隔离方式与最小权限配置。
