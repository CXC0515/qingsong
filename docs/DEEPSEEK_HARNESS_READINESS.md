# DeepSeek Harness 接入准备度

版本：1.1 · 2026-10-26
状态：接入方案已获准沉淀文档，集成实施未批准；本轮不安装、不配置、不接入。

## 依据与判断边界

用户希望未来在青松的教学助手区域接入 DeepSeek Harness。本次核对的是官方 [`deepseek-ai/deepseek-harness`](https://github.com/deepseek-ai/deepseek-harness) 及其 [架构文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)，查阅日期2026-10-26。官方将其标为developer preview，存在不兼容变更；本评估没有固定发布版本或提交，实施前必须重新核对版本和SDK协议。

框架提供插件化的模型适配、工具注册、会话日志与Agent循环，并有SDK应用配置。它可以承担执行引擎；青松的业务接入层仍需明确设计。没有运行官方安装命令、下载依赖、配置密钥或调用模型，没有把教师数据发送给框架或模型。

## 青松已有基础

- `server/context/workspaceContext.ts`、`server/middleware/authenticated.ts`：教师身份、工作区与数据/上传路径隔离；HTTP鉴权与同源变更检查已存在。
- 班级、名册、课表/日程、课堂检查与表现、批改、材料池和资料检索已有业务服务/接口。`server/routes/resources.ts` 已有搜索、资料详情和检索入口，不能称作“没有知识检索”。
- 课堂任务已有预览凭证、版本校验、operationId幂等、追加事件、结果核对；这些是可复用基础，不代表所有业务写入都已有相同保护。
- `server/services/multimodal/OpenAICompatibleProvider.ts` 等已有针对具体任务的模型调用；没有因此形成教学助手的持续会话/工具执行循环。
- 当前教学助手仅为UI预留区；代码检索未发现对应聊天会话、Agent运行或流式会话路由。

## 主要缺口

| 能力 | 需要补齐的青松接入层 |
| --- | --- |
| 会话与运行连接 | 教师/工作区到Harness会话、运行、事件日志的映射；前端发送、流式显示、停止、继续和刷新恢复。优先评估官方SDK连接，具体事件协议/生命周期需按固定版本验证，不自行再造整个执行循环 |
| 业务工具 | 将现有服务封装为有输入/输出契约的工具或插件，如查课表、查课堂记录、搜资料、预览提醒；携带真实ID、结构化错误与来源。写入走已有业务服务，不让Agent直接改SQLite |
| 当前上下文 | 显式传教师、班级、学生、项目、课次、日期和时区；明确“正在查看”与“允许操作”范围。按需取资料/历史，不能假设模型能看到React页面状态，也不能默认塞入全部学生资料 |
| 人工确认与纠错 | 聊天内显示将改什么、影响谁、预览差异、确认/取消与提交回执；将审批绑定到具体动作/参数/版本，复用课堂幂等和结果核对模式。提醒等其他写入需补齐适合自身的保护，避免断线重试重复创建 |
| 证据与可观测性 | 对话结论绑定资料页、课堂事实或任务ID，可点击回原页面；工具执行、部分失败、重试和最终保存结果有明确记录，不能仅给一句“已完成” |
| 运行治理与验收 | 后台Agent在HTTP请求结束后仍须绑定正确身份/工作区；配置执行权限、凭据管理、配额/成本、超时/取消、重启恢复与版本隔离。Harness通用执行能力按教学工具范围配置；测试跨班同名、越工作区、写入待确认、响应丢失等真实场景 |

以上是当前代码与官方架构的差距判断，不是“框架不具备这些能力”。例如框架会话日志和工具管线应复用，青松负责业务身份绑定、工具适配和用户可见反馈。具体宿主部署、并发容量与SDK生命周期尚未验证。

## 建议的最小接入顺序（仅供后续讨论）

1. 先验证一个教师会话，以及“今天有什么课”“查本班最近课堂记录”“从我的资料找依据”三个只读工具闭环；能显示来源、停止生成、刷新续接。
2. 再接一个需确认的写入，如“明天下午三点提醒收作业”：预览实际日期/时区/班级，教师确认后保存，断线后核对同一操作。
3. 最后再扩展批改、画像解释、跨任务协作及其他自动化。教案目前仍是预览入口，应单列真实生成/保存契约，不能当作现成可调用工具。

不建议把官方Web界面直接当作青松现有会话区的替代，也不预先假定独立Web服务已经满足青松多教师鉴权；优先保留现有UI，通过服务端连接引擎和受控业务工具。正式选型时再确认SDK、运行隔离方式与最小权限配置。

## 目标架构与身份配置方案

目标：教师登录一次，助手读取本人有权访问的课堂事实与资料，给出可追溯建议；需要写入时先预览、确认、执行和回读。业务权限与数据仍由青松服务端控制，Harness负责会话、模型和工具调度。

- 共享一套教学业务服务，无需每教师部署一个实例。保留现有userId、workspaceId和role；新增会话映射sessionId/runId。后台运行必须继续绑定身份，不能依赖已经结束的HTTP请求上下文。
- UID是标识，不是凭证。身份来自经过验证的登录态/服务凭证；不接受模型或客户端任意填写UID、工作区来选择数据。每次工具执行重新验证权限和有效状态，撤权后不得继续读取。
- 青松内置助手优先由后端继承登录身份。若通过HTTP MCP连接，使用绑定教师/工作区、范围、到期时间且可撤销的凭证；具体签发、存储、轮换和撤销契约须在实施方案中确定，不能复制浏览器cookie或使用共享管理员密钥。
- 私有资料为默认；未来学校共享库采用显式授权，个人库与共享库可合并检索，但不得因共享索引泄露正文、标题、摘要或引用。

推荐一个逻辑上的“青松教学业务MCP服务”，先复用当前进程与业务层，增加薄适配器，不拆成大量微服务。工具按领域分组，按需暴露。内部SDK插件也可作为备选；MCP有利于独立客户端复用，但增加传输与凭证管理。正式选择需锁定Harness版本并验证生命周期。

第一阶段拟提供：list_classes、list_students、get_schedule、query_classroom_records、search_materials、get_material。名字仅为方案，不是现存接口。当前没有可直接填入配置的青松MCP端点。

官方[MCP客户端说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md)提供stdio与Streamable HTTP；部署服务优先评估后者，配置serverName、url及凭证。具体YAML按固定版本验证，密钥不进入模型上下文。框架MCP能力不等于应用审批能力，审批由青松实现。

## 资料库RAG与业务工具的分工

| 数据 | 推荐访问方式 | 约束 |
| --- | --- | --- |
| 教材、课件、教案、教师上传资料 | RAG检索，必要时读取完整段落/原文 | 回答携带文件、页码/段落与版本 |
| 名册、课表、作业收交、课堂记录 | 结构化业务查询和确定性统计 | 读取实时事实，不能用相似片段替代精确计数 |
| 教师长期偏好 | 独立、可查看/修改/删除的偏好记录 | 不从一次对话推定永久偏好 |
| 当前对话 | 隔离的会话日志及摘要 | 历史不是已保存业务事实 |

资料处理链：上传 → 解析/OCR → 按标题、段落等结构切分 → 关键词与向量索引 → 权限范围内召回/融合 → 必要时重排与原文补读 → 带引用回答。重排是否启用、分块尺寸、召回数量和阈值均以真实中文教材/表格/扫描件样本校准，不预先伪定最优参数。

现有解析、OCR产物、资源检索与阅读入口优先复用；本次没有验证现有检索已具备向量索引、混合召回或重排，不能将拟建能力写成现状。索引保留workspace/授权范围、resourceId、资料版本、chunkId及页段定位。权限约束在召回阶段生效，原文读取再次校验；模型提示词不是隔离手段。

资料库还需：可见的处理/失败状态、失败重试、内容变更后的增量更新、删除与撤销共享后的立即拒读、旧索引清理和重建。索引是可重建派生数据，原文件与解析产物仍为事实来源；更换embedding模型/维度须记录版本并重建对应索引，不能混用。未找到依据时明确说明，模型补充建议与资料结论分开呈现。

存储方案待资料规模、延迟和运维评估后确定。PostgreSQL+pgvector是候选，暂不为此迁移现有SQLite业务数据；也可独立检索存储，通过统一检索服务隔离实现差异。先用真实样本评估权限隔离、召回、引用正确率、更新/删除生效、耗时和成本，再决定基础设施。

## 第一阶段验收任务与待决项

贯通任务：“结合我上传的教材和七年级一班最近的课堂记录，建议明天重点讲什么，并标明依据。”预期先查询当前教师可访问的班级/日期/真实记录，再检索授权资料，给出可打开的事实与原文出处。不自动写教案或改变课堂记录。

验收至少覆盖：两个教师同名班级不串数据；无权限资源不可搜索/读取；记录统计准确；引用指向正确版本/页段；资料删除/撤权后拒读；资料不足明确反馈；中断/取消可见且刷新续接；调用成本和耗时可观测。只读闭环通过后，再单独批准“提醒预览→确认→保存→回读”。

实施前待决：固定Harness版本、SDK与MCP的职责分配、凭证协议、向量模型/存储、样本基线和预算、运行隔离与日志保留。上述方案沉淀不构成安装依赖、调用模型、读取生产数据或集成开发授权。
