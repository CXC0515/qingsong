# 教师助手能力与 Memory 分阶段目标

版本：1.0 · 2026-10-28

状态：用户已确认阶段目标；阶段 0 进行中，其余阶段尚未开始。本次仅记录方案，不包含正式代码、原型修改或发布授权。

阶段 0 细化产物：[能力与记忆契约草案](ASSISTANT_CAPABILITY_CONTRACTS.md)，包含首批动作、工作状态、数据适配、验收场景和原型 v2 的具体修改范围。草案不等于能力已实现。

## 本次概要

目标是让教师通过助手完成教学系统中的实际工作，并能在数日后继续未完成的事项。主要矛盾是业务能力尚未形成完整、可靠的调用闭环；扩大记忆量不能代替业务查询、事务和执行回执。因此先规范业务契约、完成最小闭环，再扩充领域与长期记忆，最后建设主动跟进。

本文记录本聊天已确认的目标与边界，是后续专项方案的依据；每个阶段实施前仍须提交具体文件范围、风险和验证方案。产品文档、交互原型、正式实现、发布分别确认。

## 已确认边界

- 学生主体由教师在系统中手动增删。首批助手能力不修改姓名、学号、班级归属等身份信息。
- 助手可通过受控业务动作修改学生关联的动态信息，例如标签、教师观察、表现事件和课堂结果。模型推断的标签或评价先形成建议，不能自动成为正式记录。
- 页面与助手共用领域服务，能力须规范化、可调用化、原子化。一个原子动作表达完整业务意图，例如添加标签、追加观察、记录或纠正课堂结果；不等于开放单条 SQL 或任意字段写入。
- 当前事实从业务系统读取。提示词和 Skill 记录规则、字段与工具用法；Memory 保存协作意图、约定、未决问题、经验及个人偏好。记忆中的旧业务状态须带来源和观测时间，执行前重新查询。
- 身份、工作区、权限和状态变更由程序控制。历史对话或记忆不构成永久授权；有效确认绑定具体对象、参数和版本。
- 保留 DSH 与现有 SQLite 基础；不向模型开放原始数据库。成熟记忆框架作为提取、检索和整理组件评估，不能替代业务事务与执行台账。
- 用户已确认生成参数由管理员管理、系统/业务 Skill 统一维护；个人设置保留个人指令和记忆管理。具体后续开发目标与验收边界统一见[能力契约追加评审](ASSISTANT_CAPABILITY_CONTRACTS.md#已确认的后续开发目标--2026-10-28)，不视为正式实现或发布授权。

## 当前事实与目标之间的差距

以下是本轮代码与数据库结构调查的结论，不代表所有能力已交付给助手：

| 范围 | 当前基础 | 需要补齐 |
| --- | --- | --- |
| 教学查询 | 已有受控名单、课表、课堂任务、座位、提醒及部分学生记录查询，分页与日期范围有限 | 逐项声明覆盖范围；区分不可访问、失败、部分结果和确实为空 |
| 课堂记录 | 领域服务已有签名预览、版本检查、操作编号、回执及撤回机制 | 适配成助手工具并持久化协作状态；预览过期后重新核对 |
| 学生动态信息 | 学生档案及关联记录已存在 | 拆分窄范围命令；现有完整档案更新不能直接用作局部字段工具，避免遗漏参数清空其他内容 |
| 日程与提醒 | 已持久化，包含完成与重复规则 | 统一版本、幂等、历史及回执；补充稳定的学生/任务关联，明确单次与系列操作 |
| 资料与知识 | 已有资源、分块、检索与引用基础 | 尚未接入助手；验证权限、引用和检索覆盖后开放 |
| 批改 | 部分业务数据仍为 JSON 文件，已有过程状态 | 区分文件缺失与损坏；补齐事务、并发和持久任务恢复，再考虑助手写入 |
| 个人规则与记忆 | 每用户 SQLite，已有候选确认、来源、版本、到期、删除与有限召回 | 缺少结构化的跨会话工作状态、执行台账及经过场景验证的长期记忆整理 |
| 后台运行 | 已有部分任务记录 | 提醒记录不等于通知送达；需要独立的调度、执行、恢复和投递闭环 |

当前正式版本与发布记录见 [项目交接](PROJECT_HANDOFF.md)；原个人库契约见 [个人上下文](ASSISTANT_PERSONAL_CONTEXT.md)。上表是阶段规划所用调查基线，实施前须复核相关拥有者代码。

## 各阶段目标与完成条件

| 阶段 | 交付目标 | 完成条件 |
| --- | --- | --- |
| 0：契约与原型 | 确定信息归属、原子能力目录、数据库补强顺序及设置/协作原型 v2 | 每项能力明确对象、读写边界、前置条件、结果、失败与恢复方式；原型展示完整协作及跨会话继续；用户确认后才能进入对应实现 |
| 1：课堂记录最小闭环 | 接入任务查询、预览、确认、记录、复测、纠正与撤回，并保存工作状态 | 跑通读取→预览→确认→执行→核验→跨会话继续；重试不重复，断线能查结果，过时版本不能覆盖新记录，学生主体不可变更 |
| 2：动态信息与日程 | 接入标签、教师观察、表现事件和提醒的原子动作 | 标签可独立增删，记录有来源和历史；提醒具备版本、幂等与回执，关联对象可追溯；局部修改不清空其他字段，单次/系列范围明确 |
| 3：查询覆盖与后台可靠性 | 开放资料、知识和批改进展/结果查询，补齐批改存储及后台恢复 | 返回来源与覆盖范围；不可访问、错误、部分、空结果可区分；损坏数据不能被当作空数据，重启后状态准确且可恢复；批改写入另行确认 |
| 4：长期 Memory | 引入经验证的偏好、背景和经验提取、召回及整理 | 固定中文场景验证跨会话、纠正、替代、到期、遗忘及隔离；记忆有来源，当前业务事实优先；记录延迟、调用和成本；记忆组件故障不阻塞已成功的业务操作 |
| 5：主动跟进 | 建设实际的调度触发与通知投递 | 浏览器关闭仍可执行；有任务编号、执行结果和投递记录；可取消、修改、恢复，重启不重复、不丢失；不能把提醒记录存在当成通知已送达 |

阶段按依赖推进，每阶段先完成一个真实教师场景，再扩大覆盖。阶段 3 的查询扩展可按需要提前准备，但不能跳过写入可靠性要求。长期记忆的具体框架、延迟/成本预算、保留周期和质量通过标准尚未定稿，须在阶段 0 的具体契约中确定，不先承诺数值。

## 阶段 0 的具体产物

1. 信息归属表：业务事实、工作记忆、协作事件、长期偏好、显式个人规则分别由谁保存、谁可修改，以及来源与失效方式。
2. 原子能力目录：参数与缺省语义、权限、版本、确认范围、操作编号、结果查询、撤回或补偿边界；首批围绕课堂记录，不一次开放全部业务。
3. 数据适配清单：复用现有课堂事务机制；补齐动态字段窄命令和提醒契约；明确 JSON 数据向可靠存储演进的顺序，不整体重建数据库。
4. 工作状态契约：草稿、待补充、待确认、执行中、结果未知、完成、失败、取消，以及各状态允许的下一步。结果未知先查询原操作，不能直接以新编号重复执行。
5. 原型 v2：设置入口仅在展开的会话侧栏左下角；聊天区不常驻个人规则/记忆宣传文字。使用现有标准图标。恢复 OCR/评分阈值的设计讨论，并逐项标明真实支持、生效范围与待接入项。
6. Harness 披露结构：参考 Movies 对行为规则、个人偏好、能力、技能、记忆及运行参数分层披露的思路；仅提供当前模型和适配器实际支持的控制项，不做无效参数面板。
7. Memory 验证计划：选择一个主候选和一个对照，在同一教师场景下验证。ReMe 为候选、MemOS 为对照，尚未选型，也未验证与当前 DSH 版本兼容。

`docs/prototypes/assistant-settings/` 已按用户明确批准的范围更新为 v0.2 独立演示数据原型，待用户评审，未接入正式能力。契约讨论、原型评审及量化预算仍有未决项，阶段 0 尚未完成，不能将本文或当前预览作为正式实施验收。

## 目标架构的约束

工作记忆保存目标、对象引用、方案、已作选择、确认范围、未决问题、操作引用和下一步，由宿主程序维护状态。协作事件保留重要经过及理由；长期记忆保留需要跨事项复用的偏好和经验，推断内容需确认。具体表结构在实施方案中确定。

业务写入与待同步事件优先在所属业务库的同一事务内提交，再更新工作摘要或检索索引。跨库操作不能假装具有全局事务；多步业务须展示每一步的真实结果。摘要或索引失败不能把已经成功的业务操作说成失败，也不能触发重复写入。

确认过的记录保留单一权威来源，摘要和索引可重建，不建立两个可独立编辑的事实库。遗忘须覆盖后续召回和派生索引；历史日志、备份与正式业务记录按各自保留策略处理，不能宣称删除一条记忆就已物理清除所有副本。

## 验收与交付状态

每阶段分别记录：方案待确认 → 实现与检查完成 → 已部署，待用户验收 → 验收通过。只有最后一项算该阶段完成；方案确认单独标记，不能等同实现。

代码审查、自动检查及必要故障测试由 Agent 完成；网页、手机和真实教师/模型场景由用户验收。构建成功不等于已部署，健康检查成功不等于场景验收通过。原型确认不授权正式实现，实施确认不自动授权推送、合并或部署。
