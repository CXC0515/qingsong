# 备课编辑与助手协作修复

版本：v1.1 · 2026-11-05（Asia/Shanghai）
状态：PR #123已合并并部署ef6e0cf，待用户正式账号、真实模型及真机体验验收。

## 原始问题与目标

用户实际验收发现：备课页的AI助手在电脑上全屏，打开报错；插表后保存失败，表格没有明确删除入口，编辑器操作不足。目标是教师能稳定编辑教案，旁边与AI协作，明确看到AI修改范围并确认应用，保留历史恢复与Word/飞书文件互通。

## 事实、根因与验证缺口

- Workbench把非首页助手都设为modal，样式固定100dvh，导致桌面备课也覆盖正文。
- 后端创建工作区/会话后，浏览器在原生目录尚未收录时立即retain/open。SDK会拒绝unknown session/workspace；统一catch没有保留阶段，线上具体异常无法区分。
- Tiptap3.32.2真实生成的tableCell/header含align:null、orderedList含type:null，被后端属性白名单拒绝。既有测试主要喂手工JSON，未覆盖真实插表后的保存回读。
- 400明确拒绝也保留pending快照，编辑后重试仍发送旧坏内容；与网络未知结果应分开处理。
- 工具栏是自制简版，Lucide图标与Tiptap内核不等于完整编辑体验。表格仅固定3×3插入，没有删除/增删行列/合并等入口。
- 既有DOCX往返未完整保留列宽、对齐、链接及常用文字格式，不能据此宣称飞书兼容完整。

## 批准的最短实施路径

保留Tiptap/ProseMirror内核、现有DSH助手、教案版本数据库及Word转换服务。只增加共享壳层、共享内容契约和缺失的操作，不创建第二套聊天、编辑数据或云端主副本。

1. 单一持久助手从Workbench页面提到页面壳层。宽屏并排，支持收起/调整宽度；中等宽度按需右侧面板；手机保留教案与助手切回入口。编辑位置、草稿与会话不因布局变化丢失。
2. 原生导航等待工作区投影、刷新并确认会话目录、retain.ready、打开指定会话、保留或追加输入草稿，再回执成功。取消过期跳转，有界等待，错误区分同步/读取/导航。具体教案失败不打开无关空会话。
3. 前端、服务端、模型上下文、Word导入导出使用同一受控文档能力定义；按节点和属性值校验，保留原安全/身份/选区/版本边界。
4. 补齐常用格式、选中文字操作、/插入菜单；表格提供选行列数、增删行列、合并拆分、表头、列宽/对齐、删除与撤销。
5. AI入口围绕选中文字或当前表格，空表格也传明确块范围。AI生成候选仍须教师对照应用；历史版本可恢复。无选区时明确处理整篇，不把教师正文直接当自动执行指令。
6. 保存队列区分明确拒绝、结果未知和版本冲突。明确拒绝可在修正后重新保存；结果未知先复用旧操作编号；冲突保留教师输入。
7. Word输出与导入保留已提供的基础格式；使用合成样稿实际导入飞书并回读，必要时再导出Word复核。后续一键发送飞书需教师自己的账号授权及保存位置，本次不开放全平台共享bot账号，也不接实时双向同步。

## 风险、取舍和验证

主要风险是移动/隐藏iframe导致草稿丢失，格式转换静默丢信息，以及保存重试覆盖后续改稿。使用同一持久实例、共享契约、不可变历史和可确认候选控制风险。明确不支持的Office结构持续提示并保留原件。

验证从实际浏览器点击开始：插表→输入→调整→保存→刷新→删除→撤销；列表与格式同样回读。检查首次新工作区/新会话、目录延迟、已有会话重开、未发送草稿、快速切换及中断重试。宽/中/窄与短屏检查正文和助手关系；Word→飞书回读及导回样稿。模型供应商先用合成fixture验证工具/状态；真实模型质量由用户验收。生产前Linux独立检查、恢复点和源码哈希，发布后服务/匿名拒绝/资源和原有教学计数核验。

参考：飞书官方工具栏、文档表格和DOCX导入说明；借鉴内容操作方式，不复制私有编辑器或宣称所有Office结构无损。
