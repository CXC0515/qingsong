## 问题与本次范围

用户明确要求先设计原型并共同修改：聊天正文/输入区不能再出现个人规则、记忆或设置提示；快捷入口只在展开的会话侧栏左下角显示设置图标。此前设置中的OCR人工复核、自动通过及评分置信度控件被删除，用户要求保留这类指标。规则和记忆需要重新组织，保留已认可的按钮材质。

事实：原参数控件已被上次修改删除，App中的0.70、0.90、0.75变为固定值；此前控件并未完整控制后端判定。原型呈现指标与调节交互，不据此声称已经接通业务。

只修改本目录的index.html、style.css、main.js、构建产生的prototype.js/prototype.css及品牌图片副本。文档即本文。原型使用演示记录和页面内存，无API、无真实用户数据，不修改src、agent、server、生产配置或服务。

## 方案

- 延续雾灰绿背景、安静阅读面和现有按钮/连续移动选择材质，直接复用仓库玻璃运行时构建原型。
- 设置左侧按任务切换：OCR与评分、个人规则、长期记忆。指标不被记忆设置替代。
- 规则/记忆使用干净列表，编辑和来源只在进入条目后出现，不常驻双栏表单，不在每行并列多个操作按钮。
- 待确认记忆独立查看，确认前显示拟保存内容与来源；编辑、保存、停用/启用、删除反馈均仅模拟。
- 会话区保留原生侧栏的空间关系；设置图标仅在展开侧栏左下角出现，折叠后隐藏。正文和输入框周围无相关提示。
- 支持窄屏单栏和详情弹层；预览控制条可切换手机画幅。保留键盘焦点、44px控件与16px输入。

备选是继续调整现有列表上的按钮和颜色，但无法解决信息拥挤与编辑常驻的问题，因此先验证列表→详情这一结构。原型确认不等于批准正式代码接入或推送部署。

## 构建与预览

在仓库根目录执行：

```sh
./node_modules/.bin/esbuild docs/prototypes/assistant-settings/main.js --bundle --format=esm --outfile=docs/prototypes/assistant-settings/prototype.js
python3 -m http.server 4483 --bind 127.0.0.1 --directory docs/prototypes/assistant-settings
```

打开 http://127.0.0.1:4483/ 。查看「会话入口」并展开/收起侧栏；设置中分别尝试指标调节、规则编辑、记忆候选确认、更多操作。数据刷新后复原，不调用真实AI。

验证仅限构建、JS语法及本地HTTP资源可达，不进行网页验收；视觉和交互由用户评审。
