## 原始目标与授权

## 事实、未决项与路径

- 官方DSH及SDK的0.2.1-rc.3发布包可用，要求Node>=24.9.0；立项时青松生产为Node22.22.1；用户随后批准统一Node24.22.1，已通过PR #76发布。
- 当前青松已有任务专用OpenAI兼容模型配置；只核对配置存在，不输出密钥或配置内容。DSH原生模型页面支持自定义供应商、端点、协议和模型列表。
- SDK连接和原生Web模型管理不是同一个界面。已询问首批交付是工作台助手可用，还是先提供原生DSH界面；用户随后确认保留青松界面，以DSH为助手后台主体、通过业务插件复用现有服务；不再把这两种界面作为未决选择。
- 需要新增运行包与部署适配；不重新实现模型循环或供应商协议。推荐官方SDK/profile，并核对实际工具表和持久化；教师使用青松界面，模型管理使用受保护的DSH原生Web。

## 首批范围

独立worktree和`codex/harness-runtime`分支从最新origin/main创建，带入已批准的整体方案提交。

- `agent/package.json`、`agent/package-lock.json`：单独固定DSH和SDK及Node要求，不改变青松根依赖。
- `agent/`下运行探针/适配与对应部署脚本：先验证启动、模型配置、会话持久化与关闭；最终路径和配置按测试结果记录。
- 本文、整体架构及交接：记录真实执行、版本、未决项和验收边界。

## 本地运行验证结果

- `npm install --prefix agent --no-audit --no-fund`完成，固定官方发布包及SDK0.2.1-rc.3，产生独立锁文件；青松根依赖未改。安装617个依赖，本地node_modules约855MB，这是磁盘占用，不是进程内存测量。
- `npm run probe --prefix agent`通过：两个本机虚构模型请求，第一轮结束后关闭运行进程，再由原生resume恢复同一个session；第二轮请求保留前轮用户与助手历史。
- 实际请求工具表为空，输出预算128传到供应商；使用sdk-minimal仅作受控基础探针，不视为已确定最终生产profile。
- 真实模型调用0；临时会话目录已清理。未安装服务器运行时、启动正式Harness服务或修改青松界面。

## 后续渠道边界

QQ等渠道留到后续。领域工具、身份与会话服务不绑定Web组件；将来渠道适配器必须先把QQ等外部账号显式绑定到青松用户/工作区，经过同一鉴权、预算和审批。不能将群号或消息中自报的UID直接当成业务权限。本轮不配置机器人、令牌或消息发送。
