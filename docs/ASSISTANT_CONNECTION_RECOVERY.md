# 助手连接恢复与旧发布收敛

版本：1.1 · 2026-10-28 · 状态：23个旧目录清理完成，PR #99已部署，待用户网页验收。

## 问题、证据与边界

用户报告刷新后长时间停在“正在连接教学助手”，并要求清理过多旧发布。只读调查确认：正式进程正常且无重启，本次原生启动5348ms；普通请求大多在1秒内完成；会话列表返回200。502集中于上次部署切换窗口，不能用作当前持续宕机的证据。plugins/events每约60秒结束并重建，与代理统一60000ms闲置超时一致。前端只等两个目录phase=ready，没有处理初次加载失败和主动重连反馈。

事实不等于完整根因：首屏网络、资源传输和目录恢复仍需分段观察；删除旧发布只释放磁盘，不能代替连接修复。复用现有DSH，保持模型、权限和历史数据；不升级框架、不删除会话或关闭核心能力。

## 批准范围与实现

- AssistantPanel：页面载入/目录同步/失败/超时分开显示，15秒提供慢连接反馈，45秒明确未完成；用户可重连，不自动重发消息。连接尝试使用独立标识，旧页面的迟到消息不能让新页面误报成功。iframe DOM在普通刷新状态更新中保持稳定，只有显式重连改变src。
- official-ui/client.js：观察原生工作区、会话目录状态，失败立即反馈；已连接后的目录载体断开也能恢复。可信父窗口探测可补发状态，订阅随插件卸载清理。保留官方导航恢复，不创建第二套导航状态。
- officialAssistant/officialStream：SSE单独禁用代理缓冲、取消固定60秒闲置切断；每15秒重新鉴权并发送合法注释心跳，撤权/断连/早期取消均清理上游和定时器。普通请求超时不变。记录不含内容/凭据的实例、上游响应头、首块、总耗时与字节数；WebSocket鉴权失败仍403，上游连接故障503。
- 检查覆盖实际流生命周期、目录状态机、同一WebSocket上的工作区与会话控制基线、真实HTTP SSE首块、鉴权与用户隔离。网页/手机/真实模型由用户验收。

最短路径是修正协议生命周期与状态反馈并补足测量；修改仅在既有DSH适配层、共享辅助与测试，不改数据库或模型配置。主要风险是长连接泄漏、撤权后继续读取、误接受旧连接成功信号；分别以撤权/取消检查和尝试标识验证。

## 隔离Nginx慢流实验

服务器独立回环端口启动临时上游和临时Nginx，不改正式Nginx配置，不接用户数据；结束后销毁进程和临时配置。后续发现临时目录隔离不完整，默认proxy等临时目录被Nginx初始化改为nobody，具体故障与恢复见下文；不能将该实验称为完全隔离。上游800ms后结束，比较默认缓冲与X-Accel-Buffering:no：

| 模拟首块 | 默认缓冲首块 | 禁用缓冲首块 |
| --- | ---: | ---: |
| 23字节 | 805ms | 3ms |
| 约20KB（接近当前graph首帧） | 2ms | 3ms |

这是本机模拟的一组观测，不是公网或真实用户加速指标。它证明小块可能被延迟，但不能证明当前约20KB初帧的长等待全部由缓冲造成。60秒断流和错误状态缺口另有代码与正式日志证据。

## 发布后资源检查及实验副作用

公网大JS一度在约97KB后中断，Nginx error.log明确报告/var/lib/nginx/proxy写入Permission denied。检查发现目录nobody:root 0700，正式worker为www-data；临时实验没有显式指定各临时目录和user，虽然端口/配置隔离，却仍触发默认临时路径初始化，属于本次操作疏漏。

执行正式nginx -T检查后，Nginx自身将proxy/fastcgi/uwsgi/scgi目录归属恢复为www-data:root 0700，未编辑正式配置或重启服务。公网完整下载复核：JS index-BiFyGCd6.js共951282字节，SHA256 7f73f1f4e7aa8c6b2bfdf9f5dcc7f48055c009e5ba5920d8cc4643e83946bb56；CSS index-_UQIAYlx.css共163361字节，SHA256 19f6458f6acd82356ae4beba3b4e4db0d40537c48af6c1d6d0470dcdb3f6391c，均与release一致。公网ready200，回环匿名official/status401；本机链路另有一次TLS超时，不将本次检查描述为网络全程稳定。
