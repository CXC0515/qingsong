# AI 备课空间

版本：v1.0 · 2026-11-05（Asia/Shanghai）
状态：实施及验收中，尚未发布。用户已批准本专项代码、文档、检查及部署；真实课堂质量、正式网页及真机体验由用户验收。

## 本次概要与目标

教师通常下载几份参考教案和 PPT，对照课本、教辅删改自己的教案。备课空间承接这条流程：选资料 → 导入底稿或直接编写 → 按模块修改 → AI 提建议 → 教师确认 → 保存版本及导出。缺少参考稿时，可以直接依据课本、教辅开始；不强迫教师先完成一套问卷。

一个备课项目保存课题、学科、年级、教材版本、备课要求、相关班级与知识节点、明确选用的资料、教案和修改记录。教师通常多个班共用一份教案；确需不同侧重时另建教案版本。不同教学方案与同一教案的历史修订分开保存。

## 已确认事实、假设和边界

- 原页面是预览入口；已有 DSH 助手、材料池、资源教材、知识图谱和账号工作区隔离，复用这些部件。
- 参考网站来自用户交接的 Timebook 地址：`https://www.timebook.cc/column85?cateid=1024&brand=1&level=1`。链接只是教师自行寻找参考资料的入口，本次不做该站抓取、登录或整站读取。
- Hermes 教学规则用于迁移教学方法，不把历史运行、飞书交付约定当作青松已经实现的确定性流水线。青松正文和版本为本功能的保存依据。
- 保留材料池明确选择范围；本次不授权助手遍历整个材料池或任意路径，不新增学生、成绩、提醒等教学业务写入。
- 本次新增写入仅限备课项目、教案、修改候选、任务状态及必要的导入导出产物。个人记忆及规则沿用既有机制。
- 多学科共享备课工具和编辑器；语文单独加载文本研读、问题链、模板、二稿规则。其他学科采用通用教学约束，不伪装成已有同等成熟的专项 Skill。
- PPT 作为参考资料；制作 PPT 另设后续专项。导出提供 Word、PDF，不把 Word 转 PPT 当成课件设计。

## 教师操作与流转

1. 从首页“备课”进入列表，新建课题或继续已有课题。
2. 在设置中填写本次要求，可关联多个班级及知识节点；不编造班级学情。
3. 从材料池或资源教材中选择资料，也可上传到现有材料池后选用。明确底稿、教材、参考的用途；移除引用不删除原件。
4. DOCX 底稿可以导入成为可编辑正文。PPT、PDF、DOCX 可预览；文字抽取不等于看懂全部图示，必要时由视觉能力查看页面。
5. 教师可按自己的顺序编辑正文，自动保存；保存中、失败、版本冲突有明确状态。未保存内容阻止应用内离开，并可下载恢复草稿。
6. 在教案内打开助手，默认进入“备课”工作区及该教案会话。首页助手默认普通工作区；同一教案重开沿用会话。明确发起改写时将要求放入会话草稿，仍由教师发送。
7. AI 读取关联教案和已选资料，记录实际任务阶段，提出完整文档候选。选区修改受服务端范围校验；候选不会自动覆盖正文。
8. 教师查看修改内容后应用或放弃。应用前再次核对版本及资料要求，冲突时保留教师当前稿，不强行合并。
9. 历史修订可查看、直接导出 Word/PDF，也可恢复为新的修订；导出旧版不改变当前稿。不同教学方案可以从当前文档另建。
10. 任务可以停止；重启后未结束任务标为中断。已有正文、候选和任务记录保留，不声称后台无限执行或自动恢复推理。

## 实现方式与复用

业务层：`preparationDatabase` 和 repository 保存独立 `preparations.sqlite`，按登录用户与业务工作区隔离。正文、修订、候选、任务、会话关联集中由 preparationService 管理；接口和助手调用同一服务，避免两套写入规则。

文档层：共享 Tiptap JSON 作为编辑、修订和 AI 候选的统一内容结构。稳定块编号用于局部修改边界。DOCX 导入、Word 导出、PDF 转换复用文档服务，图片通过受控资产编号读取，不接受任意路径或 HTML。导出绑定不可变修订，校验文件哈希，缓存损坏可重新生成。

Harness：主 Agent 沿用 DSH。上下文组装补充当前备课、当前教案修订及选区；统一 `qingsong_discover/search/read` 增加备课、教案、已选备课资料三类对象，教案支持读取历史修订。新增唯一备课动作工具 `qingsong_preparation`，负责 begin/progress/propose/finish/render，不为每个栏目建立工具，也不直接应用建议。

Skill 路由：固定发布目录增加通用备课与语文专项，语文评审和模板按需读取；仍禁止任意文件 Skill。学科方法与工具权限分离。提示词负责教学方法，服务端负责身份、版本、选区、资料变化及状态校验。

资源与图谱：关联既有知识节点，不创建第二套知识库。检索先按允许资料、学科、年级、版本过滤，再排序；尊重页面排除状态。图谱关联及参考教案均须回到教材或来源核对，不自动写回图谱。

## 一致性与故障处理

- 写入使用 operationId 幂等键和 expectedRevision 比较，未知响应重试同一个操作；旧稿不能覆盖新稿。
- AI 任务保存起始修订、选区和资料要求指纹；候选提交及应用时检查要求变化，范围外节点不得被选区改写修改。
- 后续资料失效或变更重新鉴权和校验哈希。对象引用、会话编号均不构成权限凭证。
- 原生助手结束一轮仍未完成的任务标为中断；停止先持久化取消，再取消已有原生会话，迟到候选不能重新应用。
- 导入/导出错误说明保存状态和下一步；不支持的结构或公式明确提示，不默默删掉内容再宣称成功。
- 基础公式可编辑；复杂原始 OMML 保留以便 Word 往返，但网页 LaTeX 投影并非完整 Office 公式编辑器。

## 取舍与备选

采用现有助手与业务服务，避免新建第二套聊天、工具和材料解析框架。纯聊天直接返回长文虽更短，但不能可靠保留教师编辑和修订，因此没有作为主流程。飞书继续承担历史交付，不作为本功能必须依赖的保存后端。富文本、导入导出增加依赖成本，但比维护两套 Markdown/Word 正文更能保留教师底稿。

任务为有状态的单轮执行，提供阶段、取消和中断记录；未实现独立队列式持久推理调度器。普通助手预算不变，关联备课会话使用受限的较长预算，不无限重试。
