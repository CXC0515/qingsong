- 本次概要：复用 DSH 上下文注册机制，拆分稳定说明、会话状态、动态记忆和材料；接入开源 Mem0，替换字面召回及固定口令依赖。

## 范围与目标
正常聊天提取教师明确的个人背景及偏好，按含义召回、更新和遗忘。保留现有规则与记忆管理入口，业务事实继续查业务数据库。仅在新问题或材料状态变化时更新相关上下文，不重复组装历史和工具结果。

## 实施范围
- agent/official-teaching.mjs 及新增上下文模块：稳定说明、按轮快照、前文及材料状态。
- personalContext.ts 及新增 Mem0 服务：规则兼容、异步记忆、来源、更新遗忘和迁移。
- officialAssistant.ts：已验证的人类输入、后台任务及用户隔离。
- package.json/package-lock.json：锁定 Mem0 和 Qdrant SDK。
- 对应测试、配置样例和实施记录。无教案、独立 Router 或页面布局修改。

## 取舍、风险及验证
Mem0 增加提取及 embedding 调用，自托管 Qdrant 提供持久存储。模型与向量维度需实际配置，不能默认聊天模型支持 embedding。SQLite 保留可恢复来源及删除状态，不自动扫描全部旧聊天。记忆服务故障明确提示，不阻塞普通回答或假报保存成功。检查跨用户隔离、中文语义召回、无关结果过滤、更新遗忘、幂等、稳定上下文及原有工具回归。真实模型及网页由用户验收。

## 实际接法
### 上下文组装
复用 DSH 的 section/context 注册：固定使用规则放稳定说明，教师规则独立，相关记忆和材料列表放动态部分。DSH 继续管理消息历史和工具结果。本轮重复工具步骤复用快照；新教师消息或个人记忆工具修改后刷新。召回查询最多取最近三条教师消息、共4000字；记忆最多6项、材料摘要最多20项，不把工具结果或助理推测作为个人事实。

### 记忆
SQLite 是规则、记忆正文、版本和删除状态的事实来源。可信教师原话在回合结束后进入本地后台队列，由配置的模型提取明确个人背景和长期偏好，产生新增、更正、删除动作，证据必须逐字来自本次原话。原有规则/记忆管理接口保留。

使用 Mem0 OSS 3.3.1 的存储、更新、删除和检索接口，向量写入自托管 Qdrant。**当前使用 infer:false；新增/更新/删除决策由本项目受约束的整理服务完成，并非完全采用 Mem0 内置自动记忆流程。** 这是为了保留已有 SQLite 管理入口、来源、版本和删除状态，避免两份记忆各自变化。

向量模型为用户已配置的 SiliconFlow BAAI/bge-m3，实际返回1024维。每位用户独立集合，集合包含向量模型、维度及 Qdrant 地址标识。旧有效记忆按原文建索引，不重新推断；换索引配置后重建映射。旧聊天不做全量回溯。

召回先按向量检索，再由配置的模型筛掉与当前问题无关的候选，最后核对本地有效版本。增加这一步的依据：真实样本中，任教记忆与授课问题的余弦相似度约0.607，与游泳文本也约0.601，单靠0.55阈值不能保证相关。筛选仅在有候选时请求，超时12秒；失败不把未经筛选的记忆送给助理。该步骤会增加一次模型调用和回答前等待，尚无生产延迟与命中率指标。
