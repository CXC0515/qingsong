# Node24运行时统一

版本：1.0 · 2026-10-26
状态：已发布（PR #76，70af83d）；真实用户验收仍待用户。

## 问题、事实与目标

DSH要求Node>=24.9，青松生产原为22.22.1。本地已有24.11.1验证，但与服务器并不相同。用户明确同意统一运行环境，以减少部署和排查差异。

2026-10-26核对官方发布索引，Node24最新LTS安全补丁为24.22.1（2026-10-20）。本项目统一固定该版本：应用、DSH、安装构建与备份任务使用同一可执行文件；不替换服务器/usr/bin/node或影响其他项目。旧22运行时只用于原发布恢复，不作为新的并行运行方案。

## 最短路径与范围

- 根及agent的package.json/锁文件、.node-version、.nvmrc统一版本约束，依赖版本不升级。
- ops/linux/install-node-runtime.sh从Node官方HTTPS来源下载并校验SHA256，安装到/opt/teacher-dashboard/runtimes/node-v24.22.1-linux-x64，拒绝覆盖已有不同目录。
- 应用与备份systemd模板使用固定可执行路径和PATH，现有EnvironmentFile保持原样，不打印凭据。
- 新发布目录分别重新安装根/agent依赖，避免Node22编译产物误用于Node24；原发布目录不修改。
- 文档更新当前版本及事实，现有业务API、名册schema和业务记录不变。

备选是Node22/24各自维护。它不会天然冲突，但用户选择统一，因此不采用为正式运行方案。

## 风险与验证

原生SQLite/图片模块、运行路径、systemd沙箱和备份任务可能受影响。先在24.22.1隔离环境检查原生SQLite读写、图片处理、类型/构建、认证/隔离/名册/备份等专项、DSH虚构模型与持久会话恢复。服务器检查通过并创建在线恢复点后，才切换发布目录与服务启动路径。

保留原Node22、旧发布、旧服务定义的恢复副本和既有手工恢复点；不恢复旧数据库，不清理其他会话或真实数据。线上健康与模块探针不替代完整真实教师验收。本轮Node统一不代表教学助手界面已经接通。

## 本地验证

精确Node24.22.1下，类型检查、构建、全部219项测试通过；内存SQLite建表/写读、sharp图片缩放通过。DSH固定版本探针2次虚构模型请求、会话关闭后恢复通过，真实模型调用0。服务器独立安装后，同样全部通过；已切换应用至新发布与Node24.22.1。
