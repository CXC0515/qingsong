# 助手查询与连接修复

版本：1.0；日期：2026-10-27；状态：用户批准实施、推送、PR合并及部署，网页/真实模型体验由用户验收。

## 本次概要
用户询问两个班一号学生及性别时，模型把班名传入内部classId，后端却把参数错误统报为需要重新登录；名单投影还遗漏性别。助手代理将所有资源设为no-store，刷新重复下载，首次还涉及个人进程启动及会话连接。

最短路径：增加classes只读发现接口，名单返回既有gender，缺失/错误classId、日期、身份失效、无权限、排队和内部失败分别反馈；不猜测班级、不跨身份兜底。工具说明增加先取真实ID的调用方式，系统提示词不变。

缓存：仅已认证请求的JS/CSS可私有缓存；内容哈希assets长期缓存，未绑定内容版本的plugins每次校验，HTML/API/SSE仍no-store，Vary包含Cookie。每次到达服务端仍鉴权，不使用公共缓存。未缓存会话、业务数据和凭据。

计时：Server-Timing区分实例准备和上游响应；安全日志只记运行时启动、认证交换、工作区准备耗时，以及工具错误代码，不记录学生/凭据/问题内容；浏览器控制台记录页面连接总时长。保持10分钟回收，不增加常驻进程。

## 范围与取舍
- agent/official-teaching.mjs：公开classes及明确classId契约。
- teachingQueries.ts：班级发现与性别投影，所有查询保留工作区上下文。
- officialResponses.ts：集中错误分类、静态资源缓存规则；officialAssistant.ts接入并增加计时。
- AssistantPanel.tsx仅增加控制台耗时，不调整布局。
- 相关单测、原生HTTP集成和本专项/统一交接文档。

旧SDK发送路由已410，旧teaching-plugin仅历史运行及模型管理guard使用，本次不重新启用或扩改。课堂classId/日期入口复用相同校验和分类。备选的模糊班名匹配会引入重名误读，不采用；全部常驻和跨用户共享进程也不采用。

## 验证与边界
隔离样本验证双班一号及男女、班名误作ID/缺ID、缺失/非法日期、伪造workspace及跨用户访问；原生假模型验证classes成功和错误classId反馈，不触发真实供应商费用；HTTP验证静态资源private、ETag/304、匿名401、HTML不缓存及原会话/反馈/取消/重启/撤权检查。类型、构建、原系统提示词全文hash契约检查。网页、手机、真实模型效果由用户验收，不宣称已完成。
