# 课堂课次续接与项目改名

版本：1.1 · 2026-10-26
状态：已随PR #72发布，真实使用待用户验收。
本次概要：在既有快记、事件追加、版本校验与保存队列上补充课次绑定和项目改名，不迁移原始结果。

## 教师的操作与系统边界

从工作台“今日课表 → 去记录”进入，班级、实际日期与具体节次随入口传入。选择项目后直接点学生；仅浏览不创建空检查。首笔实际记录在一个数据库事务内建立检查与课次关联。

同一课程标识、实际日期、项目再次进入时，自动续接该课次最近一轮。另一课程或另一日期独立；自由记录也单独续接。明确点击“新一轮”才产生下一轮候选，仍在首笔写入时创建。轮次数值沿用本班、本项目、当天的全局递增编号，因此某节课可能显示第1、第4轮；选择器只提供本课次的轮次。这样返回早先课程加测不会占用其他课程的轮次。

历史待跟进仍按既有 taskId 打开，查看或跟进不会新开轮。课次标识、日期、班级和账号记录在 URL，刷新可恢复入口；URL 本身不授权，服务端在当前教师工作区重新校验课表。手动改日期、换班级或选择自由记录会退出课次绑定。课表删除或安排变化时暂停新写入，提示从历史核对；已经保存且丢失响应的同一 operationId 仍可直接查询或幂等重试。

表现记录也携带课次快照：课内界面只显示该课次，自由记录只显示自由记录，学生画像按所选日期范围汇总所有来源。撤销指向原事件，保留原事实；即使课表删除，已存事实仍可撤销。

## 项目名称和历史事实

项目 key 是身份，名称是可修改的目录元数据。默认和自建项目都可改名，更新本教师各班项目目录；结果、次数、检查标题及事件快照保留。历史与画像可以同时读取当前项目名及原始快照，不能通过字符串改写历史事件。

改名携带 operationId 与 expectedVersion。同一操作重试返回同一结果；并发版本过期整次拒绝。结果未知时保留浏览器核对标识，查询或重试原操作，不重新生成编号。读最新版本后才确认下一次变更。

名称按空白归一、同类目录不重名。自定义项目目录原有 label 列带唯一约束，改名事务同步更新该目录列与版本元数据，保证改名前的旧名可被新项目使用；事件的 projectLabel 不变。创建操作重放/查询读取当前目录名，避免将旧名称重新塞回界面。

## 数据与接口

roster schema 14 → 15，只新增三张表，不改写既有检查、轮次或事件：

| 表 | 用途 |
| --- | --- |
| classroom_lesson_rounds | 课次、日期、项目、轮次 → 既有 taskId，保留课程快照 |
| classroom_project_names | 当前名称与单调递增版本 |
| classroom_project_renames | 幂等改名结果与请求指纹 |

旧 quick_rounds 没有课次关联，继续作为自由记录；不推断旧课次。课次记录仍使用原 quick_rounds、quick_requests 和检查事件表。课表外键不绑定 schedule_items，删除课表不会抹除历史快照。

- GET quick-context / POST quick-record：可选 scheduleItemId；上下文凭据绑定课次快照。
- POST /api/classroom-tasks/projects/rename：operationId、projectKey、name、expectedVersion。
- GET /api/classroom-tasks/projects/renames/:operationId：丢响应后的结果查询。
- GET /api/classroom-behavior：scheduleItemId 或 freeOnly，原画像无这些筛选时继续汇总全部。
