# AI 教案连续写作与编辑器交互

版本：v0.2；日期：2026-11-10；状态：实现与本机验收完成，Linux 验收完成，待合并发布。网页读取与 Skill 不在范围内。

## 本次概要

把教师持续编辑教案与 AI 修改建议之间的保存、引用、只读、反馈及恢复接顺，并完成此前提出的块格式/移动交互、图片模型能力核对和既有教案功能回归。公开网页、文件下载和全网搜索暂缓；任何教学 Skill 均不修改。管理后台和工作台不在本专项范围。

## 已确认问题

- 教案引用固定修订号；运行上下文要求读取旧版，正文变化后要求教师重新添加引用。
- 普通整篇引用也走严格修订拦截，误用“重新选择段落”的提示。
- 引用按修订和选区生成独立 ID，同一文档的历史引用可能造成目标歧义。
- 教案任务提示把 needs-input 一律显示为“需要补充”，收起状态仅在组件内，重新进入会再次显示；返回任务会话还可能重加引用。
- AI 候选页面对比当前正文和候选，没有保存生成时的底稿；候选过期只有禁用提示。
- 编辑器已有内容块缺少块格式/移动操作；既有空段落加号逻辑需保留并按内容状态区分。
- 当前图片能力门禁将未声明能力和明确不支持合并报错；本地未有生产有效模型配置的证据，须在运行环境只读核验，不能推断配置错误。

## 目标流程

引用某份教案一次后，后续轮次以该文档为目标读取最新已保存稿。AI 准备生成正文修改建议前，确认草稿保存完成；修改期间该文档只读，普通问答和其他文档不锁定。生成结果始终是教师确认的候选。结束、失败、停止及刷新恢复均按服务端实际任务状态决定是否解锁。

## 实施范围

1. 将教案对象身份与每轮读取修订证据分开。普通引用继续指向文档对象；每轮保留真实读取修订。历史消息与修订不回写。只对选区引用做块 ID/文本位置复核；整篇引用不因修订变化而要求重发。
2. 在助手提交“修改正文”请求前走现有保存队列，并对当前目标文档建立前端只读状态。服务端现有任务状态作为刷新/断线恢复依据。锁定期间禁止正文编辑、导入底稿、恢复历史及应用其他候选；材料查看、阅读、停止和一般聊天保持可用。明确终态后解锁。
3. 移除页面常驻 needs-input/失败浮层。任务入口保留，并显示按状态命名的记录；继续任务只打开原会话，不自动插入引用。只有任务属于当前文档且有可定位原生消息 ID 时尝试跳转；无消息 ID 则退化为打开原会话，不猜测消息位置。
4. 记录候选生成时不可变底稿快照，使对照呈现底稿、建议和当前稿三者语义。旧建议不能覆盖新稿；提供沿用原任务要求重新生成的入口。若现有任务/候选结构无法在不迁移旧数据的前提下存快照，先使用候选的 baseRevision 读取不可变修订；仅在源码确认修订不可读后再评估追加存储。
5. 编辑器空段落保留加号；有内容的块被选中或激活时显示对应类型图标和六点手柄。类型图标打开格式菜单，手柄提供拖动/整块操作；桌面显示落点，手机提供上移/下移。文字选择菜单继续独立。先复用现有稳定 block ID 与 ProseMirror 单事务、undo/save 队列，不引入新编辑器。表格整块移动，列表和分栏结构不可拆坏。
6. 核实当前模型路由、有效模型配置和 SDK 图片能力映射。将 unknown 与明确 text-only 分开反馈；只更正有证据的登记。通过合成图像测试材料页和聊天图片门禁，不调用真实供应商、不更换模型。公开网页读取维持现状。
7. 对会话导航、保存队列、历史版本、表格、图片、分栏、Word/PDF 导入导出和响应式布局做专项回归。修复仅限此次触及的教案/助手/编辑器连接，不改 Workbench 页面或管理员后台。

## 风险、取舍与恢复

保留不可变修订、旧引用、任务、候选和会话；不批量重写、不删除。引用行为改变的风险由每轮读取版本记录、多文档澄清、任务按文档锁定和应用前版本检查控制。浏览器关闭或服务重启造成的任务中断按服务端终态解除锁定，不把未确认操作显示为成功。外部真实模型能力与正式账号行为不由合成测试背书。

## 验收

- 同一文档引用一次，AI 提建议并由教师应用；教师继续手工编辑后可接着对话，读取最新稿，不要求重新发引用。
- 修改运行时当前文档只读且其他文档可操作；停止/失败/完成/刷新后锁状态与服务端一致，正文不会被候选自动覆盖。
- 多份教案不能串稿；旧引用合并到同一文档目标；过期选区仅在无法可靠定位时才要求重选。
- 任务旧记录不浮出；缺信息在聊天中具体表达；返回记录打开原会话，不制造引用。
- 候选对照基于实际生成底稿；过期候选不能应用，重新生成保留原要求。
- 空行显示加号；有内容块显示类型图标与六点手柄；格式、整块移动、撤销、保存、刷新和分栏/表格结构通过桌面与手机操作检查。
- 图片能力未知与明确不支持反馈不同；合成图像回归通过，未调用真实供应商。
- 类型检查、构建及相关测试通过；实际应用壳层覆盖宽屏、手机窄短屏与横屏。未能正式账号/真实模型/物理手机验收的项目如实注明。

## 实现与验收记录

- Harness 工具与上下文：同一教案历史引用归为同一对象，每轮读取最新保存版本；历史预览仍读取原版本。明确选区始终保留边界，块 ID 和原文变化校验失败时要求重选，多文档或多选区不猜测。未修改任何 Skill。
- 页面与业务接口：AI begin 前通知同账号工作区的已打开页面先只读并保存草稿，所有页面确认后捕获生成底稿版本。保存失败、断线超时或取消时不开始写入。服务端 queued/running 按文档阻止保存、恢复历史、导入及候选应用；终态解锁，SSE 即时刷新并保留轮询恢复。只读切换不重建编辑器，不丢撤销历史。
- 候选：从不可变 baseRevision 读取真实底稿，读取失败明确提示并提供重试，不以当前稿冒充底稿；建议尚未应用。过期建议不能覆盖，沿原会话和原要求准备重新生成，由教师发送确认。
- 编辑器：空段落加号；非空块类型图标、六点手柄、上移/下移。桌面拖动显示落点；表格/列表完整移动，分栏内部不跨栏，单次撤销。浮动控件避开裁切并随可用视口定位，手机按钮 44px。
- 图片只读核验：2026-11-09 实际生产路由 qingsong/gpt-6-luna 的 models[].input 未配置，所用 SDK 的 DEFAULT_INPUT 为 text，resolveModelInfo 从 resolvedModel.input 映射 inputModalities。因此“当前路由不支持图片”不能推导供应商模型不支持图片。本次仅把未知能力与纯文本有效路由的反馈分开；未改模型、凭据或生产配置，未调用真实供应商。
- 本机固定 Node 24.22.1 类型检查和生产构建通过；90 项教案/Word/表格/公式/分栏/材料门禁/保存队列回归通过，追加 2 项保存握手与选区连续编辑检查通过。Linux 先前全套 207 项通过；最终新增差异及材料读取追加检查另行记录，不把中间通过当成最终产物验收。
