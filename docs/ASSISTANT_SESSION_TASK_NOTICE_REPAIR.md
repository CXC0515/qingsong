## 获批方案

用户批准本轮具体方案：补工作台所选会话内容加载诊断，修复备课失败与补充提示重叠；保留已有改动与教师记录，不修改 Skill。

基线 origin/main e51ac6e；独立分支 codex/assistant-session-task-notice。母文件夹已有 client.js 改动及未跟踪内容不变。

事实：两类提醒有独立绝对定位宿主但使用同一锚点，同时出现会重叠；工具栏 white-space:nowrap 向正文继承又会导致窄屏截断。原会话目录接口成功不证明选中会话正文已就绪，原故障尚未用正式账号复现。

最短路径是复用现有 DSH retain.ready 观测原生选中会话，并统一提示面板；不重建导航、不删除历史、不修改服务端或模型配置。风险是观测引用造成额外生命周期或旧状态覆盖；通过取消、释放和迟到结果回归检查。

## 实现

- 页面层：需要补充与旧失败提示放入同一个定位面板，正文换行、状态间分隔、面板可滚动。保留独立收起、失败五秒自动消失和任务记录。关闭触控区为 44×44px。
- Harness 的浏览器适配层：原生主视图选中会话后观测共享初次内容加载；仅传阶段及耗时，不传编号、正文、模型输入或原始错误。15秒慢加载、45秒停滞，晚到成功可恢复。切换和卸载取消旧观测并释放引用；诊断失败不改变目录连接主流程。
- 这不是原生产加载故障的根因修复，也不证明 React 正文绘制完成。目录与内容的阶段日志帮助后续区分失败环节。
